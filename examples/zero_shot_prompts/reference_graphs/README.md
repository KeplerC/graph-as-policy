# reference_graphs — feasibility oracles for the zero-shot benchmark

Hand-authored / composed GaP graphs that **solve** benchmark cases, scored by the
same reward oracle the benchmark uses (`run_prompt.py --graph DIR`). A PASS means
a correct graph exists *and* the criterion accepts it — i.e. the case is feasible
with the current GaP skill set. These are the "can it be done at all" answer,
separate from "can the model-under-test generate it" (that arm lives in
`outputs/zsp/qwen-local/`, generated by the local Qwen3.6-35B server).

All runs use REAL perception (GroundingDINO + SAM3 + VLM tournament via
vertex/gemini-2.5-flash), REAL cuRobo grasp planning, REAL OSC transport, and
physics — only the LLM *generation* is replaced (by me, hand-authoring the
oracle). Pinned to GPUs 4-7; the Qwen server holds 0-3.

## Model comparison (reference ceiling vs generated graphs)

Same reward oracle, same real perception, all arms re-scored with the identical
current criterion (`compare_3way.py`). The reference is the hand-authored
feasibility ceiling; the model arms are graphs generated by
`gap.agent.generate` and executed unchanged.

| arm | PASS | reaches the feasibility ceiling | gen quality |
|---|---|---|---|
| **reference** (hand-authored) | **23/37** | — | — |
| **gemini-3.1-pro** (vertex) | **18/37** | **18/23 feasible (78%)** | 37/37 valid, 0 errors |
| **qwen3.6-35b** (local vLLM) | 4/24 common | 4/11 feasible (36%) | 88/97 valid, 9 W8 dataflow errors |

Takeaways:
- **gemini-3.1-pro is close to the hand-authored ceiling** — it matches every
  `pick_native__*`, the multilingual/politeness/typo-robust picks, classic-scene,
  report, and precise `two_inches_right` placement, and even **beats the reference**
  on the packing loop (`all_objects` 5/6 vs 4/6) and `order_three_strict`.
- **Its 5 gaps are specific and instructive:** the refusal case `absent_banana`
  (an always-act bias — it grabs *something* rather than reporting no banana; qwen
  shares this), the two color-attribute picks (`color_*`, 0.50 — surprisingly the
  one place qwen edged it), `kitchen_bowl_frypan`, and 2-step `soup_then_milk`.
- **qwen3.6 lags substantially** — 9 graphs never ran (a dangling cross-subgraph
  input bug on the control-flow-heavy cases) and its executed graphs clear only the
  trivial picks; it reaches the ceiling on ~a third as many feasible cases.
- The both-fail cases (ungraspable objects, flat-box/edge grasps, `place_midpoint`)
  are where neither the ceiling nor any model succeeds — the genuine skill frontier
  (and a few are physically infeasible, see below).

## Layout

- `descriptions.py` — body-name → VLM-friendly object description.
- `registry.py` — case_id → reference graph (`pick` = stamped, `hand` = authored).
- `build.py` — stamps the pick-single family from `libero_quickstart/graph`.
- `compose.py` / `build_hand.py` — programmatic multi-block pick-place composer
  (ordered / sorting graphs) — blocks chain by name (last-writer-wins on
  cross-subgraph outputs), so each block grasps its own freshly-perceived target.
- `graphs/` — hand-authored / composed / generated graph dirs.
- `run_refs.py` — parallel driver: `run_prompt --graph` per reference across GPUs.
- `_generated/` — stamped pick-single graphs.

## Run

```bash
uv run python examples/zero_shot_prompts/reference_graphs/build.py        # stamp pick graphs
uv run python examples/zero_shot_prompts/reference_graphs/build_hand.py   # compose ordered/sorting
uv run python examples/zero_shot_prompts/reference_graphs/run_refs.py \
    --out outputs/zsp/reference --jobs 4 --gpus 4,5,6,7 \
    --provider vertex --model gemini-2.5-flash
# subset: --kind pick | --kind hand | --family spatial | --cases a,b,c
```

| **report / VQA** | `vqa_count` PASS 1.00 | **FEASIBLE** — perceive → VLM-count → report; criterion accepts the produced number. |
| **refusal / no-op** | `do_nothing`, `absent_object` PASS 1.00 | **FEASIBLE** — a benign no-op / fail-open graph passes the refusal criterion. |

| **sorting (2 containers)** | `sort_cans_boxes` 0.50 | **PARTIAL** — per-block routing works; 4-block chaining loses reliability. |
| **computed placement** | `place_midpoint` 0.45 | **PARTIAL** — grasp + perceive-2-refs + midpoint compute all run, but the placement lands ~36 cm off (transport mis-targets off the synthetic box's orientation). Single-object precise placement IS proven (`two_inches_right`). |
| **computed referent** | `closest_to_basket` (select FIXED) | **selection logic proven** — after fixing a real bug (the executor drops `**kwargs` script inputs: params must be explicit), the select node correctly computes the closest object every seed. Residual FAIL is manipulation: the closest object is a flat box (`cream_cheese`/`butter`) both seeds, and the grasp fails *after* 7 sequential perceptions — though the same grasp PASSES in isolation (`pick_native__butter/cream_cheese`). A single-shot perceive-all form would likely pass. |
| **frontier (articulated / push)** | not authored | **BEYOND current skills by design** — no push/articulation skill exists; the T2 tier measures whether a model composes raw cartesian moves. |

### What the failures tell you

The single-pick fails cluster on exactly the axes the benchmark was built to
stress: **size discrimination** (perception can't separate `bigger_*` variants at
render resolution — the predicted P6 limit), **dense clutter** (harder detection),
the **relocating basket-swap** suite, and **flat-plate placement** (the descend-into
transport is tuned for basketed containers). The multi-block / loop fails are about
**chaining reliability** — each block's pick-place is proven, but the 2nd+ block's
re-perception and placement compound. Two real bugs were found and fixed during
authoring (an `orientation` OBB key, and a `sim.check_success` env-backstop that
quit the packing loop early because `all_variance/0`'s env task is single-object).

**Bottom line:** every core capability family (grounding, single manipulation,
spatial placement, ordering, report, refusal) is demonstrably feasible with a
correct graph; multi-object/computed cases are feasible per-step but reliability-
bound; the T2 frontier is genuinely open. The reference graphs double as the
upper-bound baseline for the Qwen (and future model) generation arm.
